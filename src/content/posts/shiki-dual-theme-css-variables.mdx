---

I wanted code blocks that follow my theme toggle instead of the OS setting, which
means dual themes plus a plain attribute selector. The Astro side of that is two
lines of config:

```js
markdown: {
  shikiConfig: {
    themes: { light: 'vitesse-light', dark: 'vitesse-dark' },
    defaultColor: false,
  },
}
```

`defaultColor: false` is the part that matters. Without it Shiki bakes the light
palette into the inline `style` attribute and emits a `prefers-color-scheme`
media query for the dark one, which an attribute toggle cannot reach.

## The prefix disagreement

Then I hit a small research problem. One write-up said the emitted variables are
`--astro-code-*`, on the reasoning that Astro renames them to avoid clashing with
a raw Shiki install. The [Astro syntax highlighting
docs](https://docs.astro.build/en/guides/syntax-highlighting/) said `--shiki-*`.
Both are plausible, and guessing wrong means writing CSS that silently does
nothing.

So I built one page with one fence and read the HTML:

```html
<pre class="astro-code astro-code-themes vitesse-light vitesse-dark"
     style="--shiki-light:#393a34;--shiki-dark:#dbd7caee;
            --shiki-light-bg:#ffffff;--shiki-dark-bg:#121212;overflow-x:auto"
     tabindex="0" data-language="ts">
```

On Astro 7.2.4 it is `--shiki-*`. The class is `astro-code`, so the *class* got
the Astro prefix and the variables did not.

## Both rule sets, not just the override

The second thing the output tells you is easy to miss. Since `defaultColor: false`
removes the baked colour, light mode has no colour either. A stylesheet with only
a dark override leaves light-mode code blocks rendering in whatever your body
colour happens to be, which in my case was a perfectly readable grey that looked
intentional. That is the worst kind of bug.

```css
.astro-code,
.astro-code span {
  color: var(--shiki-light);
  background-color: var(--shiki-light-bg);
}

html[data-theme='dark'] .astro-code,
html[data-theme='dark'] .astro-code span {
  color: var(--shiki-dark) !important;
  background-color: var(--shiki-dark-bg) !important;
}
```

The `!important` is not laziness. Shiki writes the variables into an inline
`style` attribute on every span, and inline styles outrank a stylesheet rule of
any specificity.

Five minutes of reading build output beat a day of debugging invisible CSS.
